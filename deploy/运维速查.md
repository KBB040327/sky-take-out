# 苍穹外卖 · 部署与运维速查

> 部署目录：`/root/sky-deploy`
> 所有 `docker compose` 命令**必须**在这个目录下执行（或用 `-f` 指定文件路径）

> 🔑 **下文命令里的 `$MYSQL_PASSWORD` / `$REDIS_PASSWORD` 是变量**，真实值在
> `/root/sky-deploy/.env` 里（该文件已加入 `.gitignore`，不会进版本库）。
> 用之前先取值：
> ```bash
> cd /root/sky-deploy
> export MYSQL_PASSWORD=$(grep MYSQL_PASSWORD .env | cut -d= -f2)
> export REDIS_PASSWORD=$(grep REDIS_PASSWORD .env | cut -d= -f2)
> ```

## 一、开机自动启动（不用管）

**虚拟机重启后，服务会自己起来。** 实测数据：

```
系统引导         16:54
Docker 服务      enabled → 自动启动
容器             restart: always → 自动启动
应用就绪         16:54:57（开机后约 20 秒）
各容器重启次数    0（一次成功，没有崩溃重试）
数据             完整保留（数据卷持久化）
```

**三重保障：**

| 层级 | 机制 | 配置位置 |
|---|---|---|
| ① Docker 服务 | `systemctl enable docker` | 开机自启 |
| ② 容器 | `restart: always` | docker-compose.yml |
| ③ 启动顺序 | `depends_on: condition: service_healthy` | 等 MySQL/Redis 健康后才起应用 |

**为什么顺序不会乱？** 启动日志里能看到：

```
sky-redis  Starting ┐
sky-mysql  Starting ┘  ① 先起数据库和缓存
sky-redis  Healthy  ┐
sky-mysql  Healthy  ┘  ② 等健康检查通过
sky-app    Starting    ③ 才起应用
sky-nginx  Starting    ④ 最后起网关
```

## 二、日常命令速查

### 启停

```bash
cd /root/sky-deploy

# 启动（容器不存在会创建，配置有变化会重建）—— 最常用
docker compose up -d

# 停止容器（保留容器和数据）
docker compose stop

# 停止并删除容器（数据卷保留）
docker compose down

# ⚠️ 危险：连数据卷一起删（数据库会被清空！）
docker compose down -v

# 重启某个服务
docker compose restart app
```

### 状态与日志

```bash
# 查看状态（含健康检查）
docker compose ps

# 跟日志（Ctrl+C 退出）
docker compose logs -f app

# 看最近 100 行
docker compose logs --tail 100 app

# 看所有服务的日志
docker compose logs -f
```

### 修改代码后重新部署

```bash
# 在 Windows 上重新打包
mvn clean package -DskipTests

# 传到虚拟机
scp sky-server/target/sky-server-1.0-SNAPSHOT.jar \
    root@192.168.186.128:/root/sky-deploy/sky-server.jar

# 在虚拟机上重建应用镜像并重启
cd /root/sky-deploy
docker compose up -d --build app
```

### 排查问题

```bash
# 进容器内部
docker exec -it sky-app bash
docker exec -it sky-mysql bash

# 连数据库
cd /root/sky-deploy
export MYSQL_PASSWORD=$(grep MYSQL_PASSWORD .env | cut -d= -f2)
docker exec -it sky-mysql mysql -uroot -p"$MYSQL_PASSWORD"

# 连 Redis
export REDIS_PASSWORD=$(grep REDIS_PASSWORD .env | cut -d= -f2)
docker exec -it sky-redis redis-cli -a "$REDIS_PASSWORD"

# 看容器为什么挂了（重点看 ExitCode 和 OOMKilled）
docker inspect sky-app --format '{{.State.ExitCode}} {{.State.OOMKilled}} {{.State.Error}}'

# 看资源占用
docker stats

# 看磁盘占用
docker system df
```

## 三、三个容易搞混的命令 ⭐

| 命令 | 做什么 | 读配置变化吗 | 耗时 |
|---|---|---|---|
| `docker compose start` | 启动**已存在**的容器 | ❌ 不读 | 约 12 秒 |
| `docker compose restart` | 重启容器（不重建） | ❌ **不读** | 约 15 秒 |
| `docker compose up -d` | 创建/重建/启动 | ✅ **读** | 视情况 |

> ⚠️ **最常见的新手错误：改完 `docker-compose.yml` 后执行 `restart`，发现改动没生效。**
>
> 因为 `restart` 只是把容器重启一遍，**不会重新读取配置文件**。
> **改配置必须用 `docker compose up -d`**（它会对比配置，只重建有变化的容器）。

## 四、`docker compose` 认目录

`docker compose` 默认在当前目录找 `docker-compose.yml`。所以：

```bash
# ✅ 正确：先 cd 进去
cd /root/sky-deploy && docker compose ps

# ✅ 也正确：用 -f 指定文件（适合写脚本、定时任务）
docker compose -f /root/sky-deploy/docker-compose.yml ps

# ❌ 错误：在别的目录直接跑
cd /root && docker compose ps
# → no configuration file provided: not found
```

## 五、数据存在哪 / 怎么备份

```bash
cd /root/sky-deploy
export MYSQL_PASSWORD=$(grep MYSQL_PASSWORD .env | cut -d= -f2)

# 数据卷位置（Docker 管理的目录）
ls /var/lib/docker/volumes/sky-deploy_mysql-data/_data
ls /var/lib/docker/volumes/sky-deploy_redis-data/_data

# 备份数据库
docker exec sky-mysql mysqldump -uroot -p"$MYSQL_PASSWORD" sky_take_out \
  > /root/backup_$(date +%F).sql

# 恢复数据库
docker exec -i sky-mysql mysql -uroot -p"$MYSQL_PASSWORD" sky_take_out \
  < /root/backup_2026-10-13.sql

# 看数据卷占用
docker system df -v | grep -A5 'VOLUME NAME'
```

**关键点**：`docker compose down` 不会删数据；**只有 `down -v` 会**。

## 六、端口说明

| 服务 | 容器内端口 | 宿主机 | 能从外部访问吗 |
|---|---|---|---|
| nginx | 80 | **80** | ✅ 是（唯一暴露的）|
| app | 8080 | 未映射 | ❌ 只能容器内访问 |
| mysql | 3306 | 未映射 | ❌ 只能容器内访问 |
| redis | 6379 | 未映射 | ❌ 只能容器内访问 |

**这是刻意的安全设计**：数据库和缓存不对外暴露，外部只能通过 Nginx 的 80 端口访问。

如果需要临时从宿主机连数据库调试，可以：
```bash
# 方法一：进容器
docker exec -it sky-mysql mysql -uroot -p"$MYSQL_PASSWORD"

# 方法二：临时映射端口（改 compose 文件加 "3306:3306"，然后 up -d）
```
